# GPT-6 迁移执行记录

日期：2026-10-09。结论：保留 **GPT-6.1 Sol / low** 为日常默认，关键科学主张使用 **GPT-6 Astra** 复核。一次小规模试用支持这一可用性判断，不构成全项目最优模型或统计优越性证明。

## 基线与试用

用户配置原本已是 gpt-6.1-sol / low，项目配置原本不存在。当前聊天实际运行模型未通过状态接口确认。故 Sol / low 同时是已知配置基线和日常候选，无需杜撰另一个旧模型。模型默认从用户层记录，不等同历史每轮对话的真实设置。

用户批准迁移计划后，分别以显式模型 ID gpt-6.1-sol 与 gpt-6-astra、相同 low effort 启动两组无聊天历史的独立代理；两者均成功返回。输入为 TRIAL_PROMPT.md 和同一组源码/中间稿，不提供已知问题答案，不读取彼此结果。AGENTS.md 在两组完成主要审查后新增，不能声称试用已经证明新指令长期有效。

## 设置与回退

两项项目设置已从 project-config.toml 安装到根目录 .codex/config.toml，并读回确认一致，只限定该项目的默认模型与 effort。写入前确认目标文件不存在，未覆盖现有配置。用户全局配置未改变。项目默认不是自动模型路由，也不会证明现有聊天已切换。

初次 CLI 校验使用 `codex --strict-config features list`，客户端返回 features 子命令不支持 strict-config；这次校验未成功，不能把文件写入等同于运行时已加载。

随后运行 `codex doctor --json`：`config.load=ok`，报告的工作目录为本项目，解析成功，模型为 gpt-6.1-sol；`active thread overrides=not inspected`。该诊断整体退出码1，其他环境检查没有全部通过，因此只将配置加载项记为通过，不宣称整个环境健康或当前聊天已切换。诊断未报告 effort 的实际覆盖来源，low 已通过项目文件读回确认，活跃会话仍需自身状态确认。

回退：删除本次新增的项目 .codex/config.toml 即恢复原用户层默认（本次原值也为 Sol / low）；如该文件后续增加其他配置，只移除本次两项，不整文件删除。保留试用材料用于追溯，研究源码和旧稿件保持原有内容。

官方依据：[配置层与覆盖顺序](https://learn.chatgpt.com/docs/developer-settings)、[模型选择](https://learn.chatgpt.com/docs/models)。显式会话选择可能覆盖项目默认；新会话应以状态栏或 /status 确认实际设置。
